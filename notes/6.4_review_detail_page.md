# Milestone 6.4 - Review Detail Page

## What changed
- Added a dashboard detail view that loads one saved review from `GET /reviews/{id}`.
- Made each review card in the list clickable and wired lightweight hash navigation with `#review/{id}`.
- Added structured components for the report data saved by the backend:
  - `RequirementChecklist` renders requirement text, status, evidence, and reasons.
  - `FindingsList` groups findings by category and shows severity, file path, evidence, and suggestions.
  - `RiskyFilesList` shows changed files that have risk flags.
  - `MissingTestsList` derives missing test items from findings and failed test-related requirements.
- Added a `react-markdown` fallback for reviews where structured rows are unavailable but `report_markdown` exists.

## Why this matters
The dashboard is now more than a history list. A saved review can be opened and inspected in the browser, with the important PatchProof evidence split into readable sections instead of forcing the user to read one raw Markdown blob.

## Critical implementation details
- The frontend API client now has TypeScript types for findings, requirements, changed files, and the full detail response.
- The detail page renders eleven report-oriented sections so the user can scan readiness, requirements, findings, files, missing tests, and fallback report content.
- Structured data is preferred. Markdown is only used as a fallback when the backend did not save structured report rows.
