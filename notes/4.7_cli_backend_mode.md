# Milestone 4.7 - CLI Calls Backend

**Phase:** 4 | **Date:** 2026-07-07

## What was built

The local `patchproof review` command now talks to the FastAPI backend when a
backend URL is configured. Instead of always running the parser, risk scorer, and
LLM pipeline inside the CLI process, the command can now send the collected task
and diff to `POST /reviews/local`, write the returned Markdown report to disk,
and print the saved `review_id`.

The original in-process behavior is still available as offline mode and is also
used automatically when the configured local backend cannot be reached.

## Files changed

| File | Purpose |
|---|---|
| `cli/config_loader.py` | Added `get_patchproof_api_url()` for `PATCHPROOF_API_URL` config |
| `cli/main.py` | Updated `patchproof review` to call the backend first and fall back to local analysis when appropriate |
| `tests/unit/test_cli_backend.py` | Added coverage for config defaults, backend report writing, review ID output, unreachable-backend fallback, and CLI backend routing |

## Configuration

`PATCHPROOF_API_URL` controls whether the CLI uses the backend.

| Value | Behavior |
|---|---|
| unset | Defaults to `http://localhost:8000` |
| non-empty URL | Posts reviews to that backend URL |
| blank string | Enables offline mode and skips the backend call |

Trailing slashes are stripped, so `http://localhost:8000/` becomes
`http://localhost:8000` before building the endpoint URL.

## Review command flow

```text
patchproof review --task task.txt
  -> read task text
  -> collect local diff
  -> print repo and diff summary
  -> read PATCHPROOF_API_URL
  -> if backend URL exists:
       POST /reviews/local
       write response.report_markdown to output file
       print "Review saved: <review_id>"
  -> if backend is disabled or unreachable:
       run original local parser/risk/LLM-or-basic-report path
       write local report to output file
```

## Backend request

The CLI sends this JSON payload to `/reviews/local`:

```json
{
  "task": "contents of task.txt",
  "diff": "raw unified diff",
  "repo_name": "current repo name",
  "branch": "current branch name"
}
```

The backend response must include:

- `review_id`
- `report_markdown`

The CLI writes `report_markdown` exactly as returned by the backend and prints
`Review saved: <review_id>` so the saved review can be fetched later through
`GET /reviews/{review_id}`.

## Offline fallback

Offline behavior is preserved in two cases:

1. `PATCHPROOF_API_URL` is explicitly blank.
2. The backend URL is configured, but the request cannot connect.

In those cases, the CLI runs the same local analysis flow it used before this
milestone:

- parse the diff locally
- compute risk locally
- run the LLM pipeline if `OPENAI_API_KEY` is available
- otherwise write the basic Phase 1 report

Backend HTTP errors are treated differently from connection failures. If the
backend responds with a `4xx` or `5xx`, the CLI exits with an error because the
backend was reachable but rejected or failed the review request.

## Error handling

| Situation | CLI behavior |
|---|---|
| Backend unreachable | Print a warning and run offline analysis |
| Backend returns `4xx` or `5xx` | Print the status/detail and exit with code 1 |
| Backend returns non-JSON | Exit with a clear error |
| Backend omits `report_markdown` | Exit with a clear error |
| Backend omits `review_id` | Exit with a clear error |
