# Milestone 5.6 - End-to-end GitHub App test

## Goal

Milestone 5.6 verifies that the full GitHub App flow works against a real pull request:

1. GitHub sends a signed pull request webhook.
2. PatchProof verifies the webhook signature.
3. PatchProof fetches PR metadata and diff using a GitHub App installation token.
4. PatchProof runs the review pipeline.
5. PatchProof saves the review in the database.
6. PatchProof posts the Markdown report as a GitHub PR comment.
7. Updating the PR with a new commit triggers the `synchronize` path.

## Real test performed

A real PR was opened on the installed PatchProof repository:

```text
Repository: ethiyor/patchproof
Pull request: #2
Branch: test/patchproof-webhook -> main
Task: Implement PatchProof GitHub App webhook review flow.
```

PatchProof received the GitHub webhook and posted a bot comment from `patchproof-local` with a full PatchProof report.

That confirmed these pieces were working together:

- ngrok public URL forwarded to the local backend.
- GitHub App webhook URL reached `POST /github/webhook`.
- Webhook signature verification accepted the real GitHub request.
- The GitHub App installation token flow worked against GitHub.
- PR metadata and diff fetching worked.
- The review pipeline produced a report.
- The report was saved and posted back to the PR.

## Synchronize event

After the initial PR opened event worked, another commit was pushed to the same PR branch. That is the GitHub path that emits a `pull_request` event with action `synchronize`.

Milestone 5.6 now includes a repeatable test that signs webhook payloads and verifies both events are accepted and queued:

```text
pull_request.opened
pull_request.synchronize
```

Test file:

```text
tests/e2e/test_github_app_webhook_flow.py
```

## Bugs found during the real test

The live PR test generated useful review feedback. Two follow-up fixes were made before treating the milestone as complete:

1. `pull_request.body` type handling

   The webhook parser now validates that the body is a string before storing it on the parsed event. Malformed payloads with a non-string body become an empty string instead of crashing the background task.

2. Installation token cache reuse

   Default `GitHubAppClient` instances now share an installation token cache, so separate webhook deliveries can reuse a fresh token instead of always requesting a new one from GitHub.

Both fixes have regression tests.
