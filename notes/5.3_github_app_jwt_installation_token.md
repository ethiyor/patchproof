# Milestone 5.3 - JWT Auth + Installation Access Token

**Phase:** 5 | **Date:** 2026-07-08

## What this milestone does

PatchProof can now authenticate as a GitHub App and exchange that app identity
for an installation access token.

This is the authentication layer needed before PatchProof can fetch pull request
diffs or post PR comments as the installed GitHub App.

## Files changed

| File | Purpose |
|---|---|
| `backend/services/github_app.py` | Adds GitHub App JWT creation, installation token exchange, and per-installation token caching |
| `tests/unit/test_github_app.py` | Adds mocked tests for JWT claims, GitHub token exchange, cache reuse, refresh near expiry, and error handling |
| `pyproject.toml` | Adds `PyJWT[crypto]` for RS256 JWT signing |

## Critical step 1 - Add JWT signing dependency

GitHub App authentication requires an RS256-signed JWT. The project now depends
on:

```toml
"PyJWT[crypto]>=2.8.0"
```

The `crypto` extra installs the cryptographic backend needed for RSA signing.

## Critical step 2 - Read GitHub App config from settings

The service uses the Phase 5.1 settings:

```text
GITHUB_APP_ID
GITHUB_APP_PRIVATE_KEY_PATH
```

`GITHUB_APP_ID` becomes the JWT issuer (`iss`). `GITHUB_APP_PRIVATE_KEY_PATH`
points to the `.pem` private key downloaded from GitHub.

## Critical step 3 - Generate a short-lived app JWT

`GitHubAppClient.create_app_jwt()` builds claims like this:

```python
{
    "iss": github_app_id,
    "iat": now,
    "exp": now + 60 seconds,
}
```

Then it signs those claims with the private key using:

```text
RS256
```

This token identifies PatchProof as the GitHub App itself. It is not stored in
the database.

## Critical step 4 - Exchange the app JWT for an installation token

`GitHubAppClient.get_installation_token(installation_id)` calls GitHub:

```text
POST https://api.github.com/app/installations/{installation_id}/access_tokens
```

It sends the app JWT in the Authorization header:

```text
Authorization: Bearer <app-jwt>
```

GitHub responds with an installation access token and an expiry time. That token
is what future milestones will use to fetch PR diffs and post PR comments for a
specific installation.

## Critical step 5 - Cache installation tokens safely

Installation tokens usually last about one hour. The service caches tokens by
`installation_id` in memory:

```python
_installation_token_cache: dict[int, InstallationToken]
```

A cached token is reused while it is fresh. If it has less than 60 seconds left,
PatchProof refreshes it before returning it.

The token is never stored in Postgres. It only lives in backend process memory.

## Critical step 6 - Handle failures clearly

The service raises clear `RuntimeError`s when:

- `GITHUB_APP_ID` is missing
- `GITHUB_APP_PRIVATE_KEY_PATH` is missing
- the private key file does not exist
- GitHub returns a non-2xx response
- GitHub's response does not include `token`
- GitHub's response does not include `expires_at`
