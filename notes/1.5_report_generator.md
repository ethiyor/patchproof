## Concept: Report Generation as String Building

The report is built as a Python `list[str]` — one entry per line. At the end, `"\n".join(lines) + "\n"` assembles the final string.

```python
lines: list[str] = []
lines += ["# PatchProof Report", ""]
lines += ["**Repository:** test-repo  ", ""]
# ... more sections ...
return "\n".join(lines) + "\n"
```

**Why a list instead of string concatenation?** In Python, strings are immutable — every `+=` on a string creates a new string object. For a report with dozens of lines, this creates many short-lived objects. A list accumulates items cheaply, and `join` does a single allocation. This is a standard Python pattern for building large strings.

## Concept: Deterministic Output for Testing

The `generated_at` parameter is the key that makes the report testable:

```python
def generate_report(
    ...
    generated_at: str | None = None,   # None → uses datetime.now()
) -> str:
    ts = generated_at or _now_utc()    # test passes a fixed string
```

In production: `generate_report(diff, risk, ...)` uses the real current time.
In tests: `generate_report(diff, risk, ..., generated_at="2026-07-05 00:00 UTC")` produces the exact same output every run.

This pattern — **injecting time as a parameter** rather than calling `datetime.now()` inside the function — is a fundamental testing technique. A function that reads the clock directly is hard to test deterministically; a function that accepts time as an input is trivially testable.

## Concept: Golden Snapshot Testing

A **golden snapshot test** works like this:

1. Generate output from known, fixed input
2. Compare it byte-for-byte to a committed "golden" file
3. If the output ever changes, the test fails

```python
def test_matches_golden_file():
    result = generate_report(diff, risk, ..., generated_at="2026-07-05 00:00 UTC")
    expected = Path("tests/fixtures/golden_reports/basic_report.md").read_text()
    assert result == expected
```

**What it catches:** Any unintended change to the report format — a missing blank line, a changed emoji, a reordered section — immediately breaks the test. This forces you to review format changes consciously instead of discovering them in production.

**How to update the snapshot:** Delete `tests/fixtures/golden_reports/basic_report.md` and re-run. The test auto-recreates it on the first run (and skips), then compares on every subsequent run.

**Limitation:** Snapshot tests are brittle for output with timestamps or random data. This is why `generated_at` is injectable — the test always passes a fixed timestamp so the snapshot never drifts.

## Concept: `tmp_path` Pytest Fixture

The write-to-disk tests use pytest's built-in `tmp_path` fixture:

```python
def test_creates_file(self, tmp_path):
    out = tmp_path / "patchproof-report.md"
    write_report(..., output=out)
    assert out.exists()
```

`tmp_path` is a `pathlib.Path` pointing to a unique temporary directory that pytest creates before the test and cleans up after. This means:
- Tests never write to your actual project directory
- Tests are independent of each other (each gets a fresh directory)
- No cleanup code needed
