# Milestone 6.6 - Finding Filters and Production Build

## What changed
- Added finding category filter buttons to the review detail page:
  - All
  - Security
  - Missing Test
  - API Contract
  - Database
  - Other
- Filtering happens client-side against the findings already loaded from `GET /reviews/{id}`.
- Updated backend CORS to allow both Vite development origins and same-machine production origins.
- Updated FastAPI to serve `frontend/dist` as static files when the production dashboard has been built.
- Updated Docker Compose's backend reload watch list to include `frontend`, so local dashboard build changes are visible in the compose workflow.

## Why this matters
The detail page can now answer focused questions quickly: security issues, test gaps, API-contract problems, or database risks. The dashboard can also be built once and served from the backend container for a simpler local production-style run.

## Critical implementation details
- `npm run build` creates the static bundle under `frontend/dist`.
- FastAPI mounts that folder at `/` only when it exists, so API-only development still works before the frontend is built.
- API routes are registered before the static mount, so `/health`, `/reviews`, and `/github/webhook` continue to behave as backend endpoints.
