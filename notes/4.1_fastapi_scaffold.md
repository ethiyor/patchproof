## Library: FastAPI

**What it is:** A Python web framework for building HTTP APIs. It is built on top of Starlette (the underlying web server framework) and Pydantic (for request/response validation).

**Why it's the right choice:**
- Automatic request validation using Python type annotations
- Automatic API documentation (`/docs` — Swagger UI, `/redoc`)
- Async-first — handles many requests concurrently without threads
- Fast to write — a minimal endpoint is 4 lines

**How a basic FastAPI endpoint works:**

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/health")          # method + path
async def health() -> dict:  # async function = non-blocking
    return {"status": "ok"} # dict auto-serialised to JSON
```

FastAPI reads the return type annotation (`-> dict`) and the function body, and automatically:
- Serialises the return value to JSON
- Sets `Content-Type: application/json`
- Validates incoming request bodies against Pydantic models (used in later milestones)

**The decorator `@app.get("/health")`** registers the function as the handler for `GET /health`. FastAPI maps `GET`, `POST`, `PUT`, `DELETE` to `@app.get`, `@app.post`, etc.

## Concept: async/await in Python

FastAPI is **async-first**. The `async def` keyword marks a function as a coroutine — a function that can pause and yield control while waiting for I/O (database queries, HTTP calls, file reads), allowing other requests to be handled in the meantime.

```python
# Synchronous — blocks the entire server while waiting
def slow_handler():
    result = database.query("SELECT ...")   # blocks for 50ms
    return result

# Asynchronous — pauses this handler, handles other requests during the wait
async def fast_handler():
    result = await database.query("SELECT ...")  # suspends, others run
    return result
```

**`await`** is the keyword that tells Python "this operation may take time — pause here and let others run." You can only use `await` inside an `async def` function.

**The event loop** is the runtime that manages all the pauses and resumes. Python's `asyncio` provides one event loop that handles all concurrent requests. Uvicorn runs this loop for you.

**Why this matters for PatchProof:** The backend will call the OpenAI API, query PostgreSQL, and hit the GitHub API. All three are network calls that could take seconds. With async, one request waiting for OpenAI does not block another request checking the health endpoint.

## Concept: Lifespan

The `lifespan` context manager is the correct FastAPI pattern for startup and shutdown logic:

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # --- STARTUP --- runs once when the server starts
    logger.info("Server starting")
    # e.g.: create database connection pool here (milestone 4.2)
    
    yield   # server is running, handling requests
    
    # --- SHUTDOWN --- runs once when the server stops
    logger.info("Server shutting down")
    # e.g.: close database connection pool here

app = FastAPI(lifespan=lifespan)
```

**Why `yield` in the middle?** The `asynccontextmanager` decorator converts a generator function into a context manager. Everything before `yield` is the `__enter__` (startup), everything after is `__exit__` (shutdown). FastAPI calls the lifespan context manager when the server starts and stops.

**Old pattern (deprecated):** `@app.on_event("startup")` and `@app.on_event("shutdown")` — you may see this in older FastAPI code. The `lifespan` pattern replaces both.

## Library: pydantic-settings

**What it is:** An extension to Pydantic that reads configuration from environment variables and `.env` files into a typed Python class.

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str = ""
    openai_api_key: str = ""
    secret_key: str = "changeme"

    model_config = SettingsConfigDict(env_file=".env")
```

When you call `Settings()`, it:
1. Reads environment variables first (`DATABASE_URL`, `OPENAI_API_KEY`, etc.)
2. Falls back to `.env` file values
3. Falls back to the Python default values

**Why not just `os.getenv()`?** With `pydantic-settings`:
- All config is in one place with one class
- Types are validated (if you set `port: int`, it rejects `"abc"`)
- IDE autocomplete works for `settings.database_url`
- You can't forget to handle a missing value — defaults are explicit

**`@lru_cache`** on `get_settings()` means the `Settings()` object is created once and reused. Without it, every request would re-read the `.env` file. `lru_cache` = "least recently used cache" — stores the result of the function call and returns it on every subsequent call.

## Library: Uvicorn

**What it is:** An ASGI server — the process that actually listens for HTTP connections and passes requests to FastAPI.

The relationship:

```
Browser/curl  →  Uvicorn  →  FastAPI  →  your route function
              (HTTP layer)  (routing)   (business logic)
```

**ASGI** (Asynchronous Server Gateway Interface) is the protocol that connects the server (Uvicorn) to the framework (FastAPI). It's the async successor to WSGI (used by Flask/Django).

```bash
uvicorn backend.main:app --reload
#        ^module path   ^FastAPI instance
#                               ^restart on file changes (dev only)
```

`--reload` watches your source files and restarts the server automatically when you save a change. Never use it in production.

## Concept: TestClient for Synchronous Testing

FastAPI testing uses `TestClient` from Starlette — a synchronous wrapper that lets you test async FastAPI endpoints without running a real server:

```python
from starlette.testclient import TestClient
from backend.main import app

client = TestClient(app)   # wraps the FastAPI app in a test harness

def test_health():
    response = client.get("/health")   # no real HTTP, no network
    assert response.status_code == 200
    assert response.json() == {"status": "ok"}
```

`TestClient` runs the entire FastAPI stack in-process — routing, middleware, lifespan, everything — but without opening a network socket. It uses Python's `httpx` library internally.

**Why not async tests?** `TestClient` handles the async-to-sync bridge for you, so tests stay simple `def` functions. For integration tests that need real DB connections (milestone 4.3+), we'll move to async test clients.
