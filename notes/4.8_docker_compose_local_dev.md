# Milestone 4.8 - Docker Compose for Local Dev

**Phase:** 4 | **Date:** 2026-07-07

## What was built

PatchProof now has a one-command local development environment for the backend
and database:

```bash
docker compose up
```

That command starts PostgreSQL 16 and the FastAPI backend together. The backend
waits for Postgres to become healthy, applies Alembic migrations, then starts
Uvicorn with reload enabled.

## Files changed

| File | Purpose |
|---|---|
| `Dockerfile.backend` | Builds the Python backend image and defines the default backend startup command |
| `docker-compose.yml` | Defines the `backend` and `db` services, ports, health check, env vars, and persistent DB volume |
| `.dockerignore` | Keeps `.git`, `.venv`, caches, local `.env`, and generated reports out of the Docker build context |
| `README.md` | Documents how to start, stop, inspect, and reset the local Docker Compose stack |

## Critical step 1 - Build the backend image

`Dockerfile.backend` starts from `python:3.12-slim`, sets `/app` as the working
directory, copies the project code, installs the package with `pip install -e .`,
and exposes port `8000`.

This gives the backend container all project dependencies from `pyproject.toml`,
including FastAPI, Uvicorn, SQLAlchemy, asyncpg, Alembic, OpenAI, and httpx.

## Critical step 2 - Start PostgreSQL 16

`docker-compose.yml` defines a `db` service using the official `postgres:16`
image. It creates a local development database with these values:

```text
POSTGRES_USER=patchproof
POSTGRES_PASSWORD=patchproof
POSTGRES_DB=patchproof
```

The database is published to the host at `localhost:5432`, so local tools can
connect to it while the backend uses the internal Compose hostname `db`.

## Critical step 3 - Persist database data

The `db` service uses a named volume:

```text
patchproof_postgres_data:/var/lib/postgresql/data
```

This means reviews and migration state survive normal `docker compose down` and
container restarts. To wipe the local database completely, run:

```bash
docker compose down -v
```

## Critical step 4 - Wait for database readiness

The database service has a health check:

```text
pg_isready -U patchproof -d patchproof
```

The backend service uses:

```yaml
depends_on:
  db:
    condition: service_healthy
```

This prevents the backend from trying to run migrations while Postgres is still
booting.

## Critical step 5 - Configure the backend from environment variables

The backend receives this database URL from Compose:

```text
DATABASE_URL=postgresql+asyncpg://patchproof:patchproof@db:5432/patchproof
```

Optional secrets are passed through from the host or `.env` file:

```text
OPENAI_API_KEY
GITHUB_TOKEN
SECRET_KEY
DEBUG
```

No production secret is hardcoded. The database credentials are local-only dev
credentials for the Compose database.

## Critical step 6 - Apply migrations before serving requests

The backend startup command is:

```bash
alembic upgrade head && uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload --reload-dir backend --reload-dir core --reload-dir cli --reload-dir llm --reload-dir models
```

The first half applies all pending Alembic migrations, including the initial
schema for the seven Phase 4 tables. The second half starts the FastAPI server.

## Critical step 7 - Enable live backend development

The backend service mounts the repository into the container:

```yaml
volumes:
  - .:/app
```

Together with Uvicorn `--reload`, this lets code changes on the host reload the
backend process without rebuilding the image.

## Running the stack

```bash
docker compose up
```

Expected local endpoints:

- Backend API: `http://localhost:8000`
- API docs: `http://localhost:8000/docs`
- PostgreSQL: `localhost:5432`
