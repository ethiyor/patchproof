# Milestone 7.4 - Backend Call + Report Display

## What changed

- Added `vscode-extension/src/api/patchproofClient.ts`.
- Added the VS Code setting `patchproof.apiUrl` with default `http://localhost:8000`.
- Wired the sidebar review flow to collect the Git diff, call `POST /reviews/local`, and display the returned review report.
- Added loading, backend error, and validation states in the sidebar.
- Added a small built-in Markdown renderer for headings, inline code, bullets, and paragraphs so the returned `report_markdown` can be displayed without external browser libraries.

## Why it matters

The VS Code extension now uses the same backend review contract as the CLI and GitHub App flow. Developers can run PatchProof before opening a pull request, while GitHub App reviews still run after PR creation.

## Verification target

Start the backend, open a Git repo with uncommitted changes in the Extension Development Host, enter a task, and click `Run PatchProof`. The sidebar should show a loading state and then render the PatchProof report. If the backend is not running, the sidebar should show `Could not connect to PatchProof backend. Is it running?`.
