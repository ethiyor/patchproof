## Bug Found: Untracked Files Invisible to `git diff HEAD`

**Symptom:** Running `patchproof review` when you have new files not yet committed produced a diff that was missing those files entirely.

**Root cause:** `git diff HEAD` compares the working tree against the last commit. It only knows about files git is already tracking. New files that have never been committed are "untracked" — git is not aware of them, so they don't appear in the diff output at all.

**Fix:** After getting `git diff HEAD` for tracked changes, loop through `repo.untracked_files` and generate a "new file" diff for each one using `git diff --no-index /dev/null <file>`. This command compares `/dev/null` (empty) against the new file, producing a synthetic diff that shows all lines as additions.

```python
for rel_path in repo.untracked_files:
    result = subprocess.run(
        ["git", "diff", "--no-index", "--", "/dev/null", str(abs_path)],
        capture_output=True, text=True, cwd=repo.working_dir,
    )
    part = result.stdout
    # replace absolute path with repo-relative path in the diff header
    abs_str = str(abs_path).lstrip("/")
    part = part.replace(f"a/{abs_str}", f"a/{rel_path}")
    part = part.replace(f"b/{abs_str}", f"b/{rel_path}")
    untracked_parts.append(part)
```

**Why `subprocess` instead of `repo.git.diff()`?** GitPython raises `GitCommandError` when `git diff --no-index` exits with code 1 (which it always does when files differ — it's normal). Accessing `exc.stdout` from the exception gives a formatted error string, not the raw diff. Using `subprocess.run()` captures stdout directly and avoids this entirely.

**Why `.lstrip("/")` on the path?** `git diff --no-index` uses the full absolute path in the diff header (e.g., `a/home/user/project/README.md`). The leading `/` is stripped so the replacement matches correctly (`a/home/...` → `a/README.md`).
