## Library: SQLAlchemy

**What it is:** Python's most widely used database library. It has two layers:

- **Core** — low-level: write SQL expressions as Python objects
- **ORM** (Object Relational Mapper) — high-level: map Python classes to database tables

PatchProof uses the ORM layer. You define a Python class, decorate it with table metadata, and SQLAlchemy translates Python operations into SQL for you.

---

## Concept: ORM — Object Relational Mapper

An ORM maps the "object world" (Python classes and attributes) to the "relational world" (database tables and columns).

**Without ORM:**
```python
cursor.execute("""
    INSERT INTO reviews (id, task_text, risk_score)
    VALUES (%s, %s, %s)
""", (str(review_id), task, 7))
```

**With ORM:**
```python
review = Review(task_text=task, risk_score=7)
session.add(review)
await session.commit()  # SQLAlchemy writes the INSERT for you
```

The ORM lets you work with Python objects. You don't write SQL — SQLAlchemy generates it. Benefits:
- No raw SQL strings to typo
- Python type checking on column values
- Relationships between tables expressed as Python attributes
- Database vendor differences handled automatically

---

## Concept: Declarative Base

`DeclarativeBase` is the foundation class all models inherit from. It registers each model class with a metadata registry that SQLAlchemy uses to understand the full schema.

```python
class Base(DeclarativeBase):
    pass

class Review(Base):         # inherits from Base
    __tablename__ = "reviews"  # tells SQLAlchemy which table this maps to
    ...
```

When Alembic generates migrations (milestone 4.3), it reads `Base.metadata` — the registry of all tables — to figure out what SQL `CREATE TABLE` statements to emit.

---

## Concept: Mapped types (SQLAlchemy 2.0)

SQLAlchemy 2.0 introduced a new way to define columns using Python type annotations:

```python
class Review(Base):
    __tablename__ = "reviews"

    id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True)
    task_text: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    risk_score: Mapped[Optional[int]] = mapped_column(Integer, nullable=True)
```

**`Mapped[T]`** declares the Python type of the attribute. `Mapped[str]` = always a string. `Mapped[Optional[str]]` = either a string or `None`.

**`mapped_column(...)`** provides the database-level details: which SQL type, whether it's nullable, whether it's a primary key, foreign key references, server defaults.

This two-layer annotation (Python type + DB type) is what gives you type checking in your editor AND correct SQL schema generation.

## Concept: UUID Primary Keys

Every table uses a UUID as primary key instead of an auto-incrementing integer:

```python
id: Mapped[uuid.UUID] = mapped_column(
    UUID(as_uuid=True),
    primary_key=True,
    server_default=text("gen_random_uuid()"),  # generated by PostgreSQL
    default=uuid.uuid4,                        # generated by Python (for tests)
)
```

**Why UUID over integer?**
- UUIDs are globally unique — two different databases can generate records that don't collide
- You can generate the ID in Python before inserting (useful for testing and event sourcing)
- They don't leak information: `id=7` reveals that there are 6 other records; a UUID reveals nothing

**`server_default=text("gen_random_uuid()")`** — when inserting without an explicit ID, PostgreSQL generates one. **`default=uuid.uuid4`** — when creating a Python object (not going through the DB), Python generates one. Both are needed.

## Concept: Relationships

SQLAlchemy `relationship()` links two model classes at the Python level, corresponding to a foreign key at the SQL level:

```python
class Review(Base):
    ...
    findings: Mapped[list["ReviewFinding"]] = relationship(
        back_populates="review",
        cascade="all, delete-orphan"
    )

class ReviewFinding(Base):
    ...
    review_id: Mapped[uuid.UUID] = mapped_column(ForeignKey("reviews.id"))
    review: Mapped["Review"] = relationship(back_populates="findings")
```

After loading a `Review` from the DB, you can access `review.findings` and SQLAlchemy automatically runs the `SELECT` for related findings. `back_populates="review"` wires the reverse direction.

**`cascade="all, delete-orphan"`** means: if a `Review` is deleted, all its `ReviewFinding`, `RequirementCheck`, and `ChangedFile` rows are automatically deleted too. Without this, you'd get a foreign key constraint violation.

## Concept: `ARRAY` (PostgreSQL-specific)

The `risk_flags` column on `ChangedFile` stores a list of strings:

```python
risk_flags: Mapped[Optional[list[str]]] = mapped_column(
    ARRAY(String),   # PostgreSQL native array type
    nullable=True,
)
```

PostgreSQL supports native array columns: `TEXT[]`. SQLAlchemy's `ARRAY(String)` maps to this. In Python, you read and write it as a regular list:

```python
cf = ChangedFile(file_path="auth/login.py", risk_flags=["auth", "migration"])
cf.risk_flags  # → ["auth", "migration"]
```

This is a PostgreSQL-specific feature — SQLite doesn't support it. For the tests (which run without a DB), we just instantiate the model object in Python and verify the value is stored correctly.

## Concept: Async SQLAlchemy

PatchProof uses **async SQLAlchemy** so database operations don't block the event loop:

```python
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker

engine = create_async_engine("postgresql+asyncpg://user:pass@localhost/db")
factory = async_sessionmaker(engine, expire_on_commit=False)

async with factory() as session:
    result = await session.execute(select(Review).where(Review.id == review_id))
    review = result.scalar_one()
```

**`asyncpg`** is the PostgreSQL driver that supports async. The connection URL uses `postgresql+asyncpg://` (instead of `postgresql://`) to tell SQLAlchemy to use the async driver.

**`expire_on_commit=False`** — by default, after a `commit()`, SQLAlchemy expires all attributes on the model (marks them as stale so the next access re-queries). In async code, accessing an expired attribute outside the session context would fail. Setting this to `False` keeps attribute values accessible after commit.

## Concept: FastAPI Dependency Injection

`get_db_session` is a **FastAPI dependency** — a function that provides a resource to a route handler:

```python
async def get_db_session() -> AsyncGenerator[AsyncSession, None]:
    async with factory() as session:
        yield session   # route uses this session
    # session is closed automatically after the request ends
```

Route handlers receive it via `Depends()`:

```python
@router.post("/reviews/local")
async def create_review(
    body: LocalReviewRequest,
    db: AsyncSession = Depends(get_db_session),  # injected automatically
):
    review = Review(task_text=body.task, ...)
    db.add(review)
    await db.commit()
```

FastAPI calls `get_db_session()` before the handler runs, passes the yielded session in, then closes the session after the handler returns (even if it raises an exception). This is the correct pattern for managing per-request DB sessions.
