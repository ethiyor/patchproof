## How GitPython works

Two layers:
- **High-level objects** (`git.Repo`) — Python objects for repo metadata: branch name, remotes, commit SHA.
- **Raw git commands** (`repo.git.*`) — every git subcommand as a method. `repo.git.diff("HEAD")` runs `git diff HEAD` and returns stdout as a string.

`search_parent_directories=True` walks up the folder tree to find `.git/` — essential for a CLI tool.

## git diff modes

| Command | Shows |
|---|---|
| `git diff HEAD` | All uncommitted changes vs last commit (default) |
| `git diff --cached` | Only staged changes vs last commit |
| `git diff` | Only unstaged changes |

## Key design decisions

- **`DiffResult` is a `@dataclass`** — simple internal data object, no Pydantic needed yet.
- **Fallback for new repos** — `git diff HEAD` fails with no commits; catches `GitCommandError` and falls back to `git diff --cached`.
- **`review-pr` stub** — Typer collapses a single `@app.command()` into the default command; adding a second forces multi-command mode so `patchproof review` works as a named subcommand.
