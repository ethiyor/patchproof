# Milestone 5.1 - GitHub App Registration & Config

**Phase:** 5 | **Date:** 2026-07-07

## What this milestone does

Milestone 5.1 prepares PatchProof to run as a GitHub App. It does not implement
the webhook endpoint yet; that starts in milestone 5.2. This milestone adds the
configuration, safety rules, and setup documentation needed before GitHub can
send signed webhook events to the backend.

## Files changed

| File | Purpose |
|---|---|
| `backend/config.py` | Added GitHub App settings loaded from environment variables |
| `.env.example` | Added example `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY_PATH`, and `GITHUB_WEBHOOK_SECRET` |
| `.gitignore` | Added rules so GitHub App private key files are not committed |
| `docker-compose.yml` | Passes GitHub App env vars into the backend container |
| `docs/github_app_setup.md` | Documents GitHub App registration, permissions, tunnel URL, secret, and private-key setup |
| `tests/unit/test_backend_config.py` | Verifies GitHub App settings default safely and load from environment variables |

## Critical step 1 - Add backend configuration

The backend settings now include:

```python
github_app_id: str = ""
github_app_private_key_path: str = ""
github_webhook_secret: str = ""
```

These values are loaded by `pydantic-settings` from environment variables. Empty
strings are safe defaults for local startup before the GitHub App is configured.

## Critical step 2 - Document required environment variables

`.env.example` now shows the Phase 5 variables:

```bash
GITHUB_APP_ID=123456
GITHUB_APP_PRIVATE_KEY_PATH=./secrets/patchproof-github-app.private-key.pem
GITHUB_WEBHOOK_SECRET=replace-with-a-random-webhook-secret
```

`GITHUB_APP_ID` identifies the app. `GITHUB_APP_PRIVATE_KEY_PATH` points to the
private key GitHub gives you. `GITHUB_WEBHOOK_SECRET` must match the secret typed
into the GitHub App webhook settings.

## Critical step 3 - Protect the private key

`.gitignore` now ignores:

```text
*.pem
*.private-key.pem
secrets/
```

This keeps the downloaded GitHub App private key out of version control. The
private key should live only on the local machine or in a production secret
manager.

## Critical step 4 - Pass config through Docker Compose

The backend container now receives:

```yaml
GITHUB_APP_ID: ${GITHUB_APP_ID:-}
GITHUB_APP_PRIVATE_KEY_PATH: ${GITHUB_APP_PRIVATE_KEY_PATH:-}
GITHUB_WEBHOOK_SECRET: ${GITHUB_WEBHOOK_SECRET:-}
```

That lets the same `.env` values work when running the local Docker Compose
backend.

## Critical step 5 - Document GitHub-side registration

`docs/github_app_setup.md` explains the manual GitHub setup:

1. Create a new GitHub App.
2. Give it the minimum permissions:
   - Contents: Read
   - Pull requests: Read and write
   - Issues: Read
   - Metadata: Read
3. Subscribe to `pull_request` events.
4. Point the webhook URL to a tunnel plus `/github/webhook`.
5. Download the private key and store it under `./secrets/`.
6. Copy `.env.example` to `.env` and fill in the GitHub App values.

## What remains manual

Codex cannot register the app in your GitHub account or generate the private key
for you. Those steps must be done in GitHub's Developer Settings. Once you have
the values, the backend is ready to read them.
